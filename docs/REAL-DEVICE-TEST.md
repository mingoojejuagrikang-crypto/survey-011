# REAL-DEVICE-TEST — 실기기 검증 절차

> **왜 필요한가:** iOS Safari의 STT·TTS·마이크·오디오 경로는 데스크톱 Chromium이 재현하지
> 못한다. Playwright 스위트 858건이 전부 통과해도 그건 **근사치**다.
>
> **계약:** iOS·STT·마이크·오디오·safe-area가 걸린 변경은 **실기기 확인 없이 "해결"로 선언하지
> 않는다.** 판정 전까지 상태는 `MONITORING`이지 `RESOLVED`가 아니다
> ([AGENTS.md](../AGENTS.md) 계약 4, [ENGINEERING-GUARDRAILS.md](../ENGINEERING-GUARDRAILS.md) 상태 모델).

## 무엇이 기기 게이트인가

데스크톱으로 판정하면 안 되는 축:

| 축 | 이유 |
|----|------|
| STT 생존 (탭 전환·백그라운드 복귀·TTS 연발 후) | 인식기 수명주기가 OS·브라우저 구현에 달렸다 |
| TTS 발음·타이밍 | 목소리·문장부호 처리가 기기마다 다르다 |
| 마이크 경로 전환 (블루투스 ↔ 내장 ↔ 스피커폰) | 데스크톱에 해당 이벤트가 없다 |
| 클립 청취 품질 | 기계 재인식은 사람 청취를 대체하지 못한다 (가드레일 ⑤) |
| safe-area (노치·홈바) | 브라우저는 실제 inset을 시뮬레이션하지 않는다 |
| 배터리·발열 (상시 글로우·rAF) | 측정 자체가 기기에서만 가능 |
| 원거리 판독성 (2~3m, 장갑) | 체감 판단이다 |

## 절차

### 1. 배포본이 실기기에 반영됐는지부터 확인

**배포 ≠ 라이브.** gh-pages가 "Published"여도 GitHub Pages 빌드가 조용히 스턱될 수 있고
(KNOWN-ISSUES `[DEPLOY-PAGES-STUCK-1]`), PWA 서비스워커가 구버전을 계속 띄울 수도 있다
(`[ENV-8]`).

- 앱 하단 버전 표시가 기대 버전인지 확인
- 라이브 번들 해시를 배포 산출물과 대조
- 어긋나면 재빌드하거나, 앱 안의 업데이트 배너로 새로고침

**구버전에서 낸 판정은 무효다.** 이걸 건너뛰면 "고쳤는데 안 고쳐졌다"는 결론이 나온다.

### 2. 현장 조건에 맞춰 세팅

- 이어폰 착용 (또는 검증하려는 오디오 경로)
- 폰은 실제로 쓰는 거리(2~3m)에 두기
- 세로 고정 (가로는 `PortraitGuard`가 막는다)
- 소음 조건이 쟁점이면 실제 환경에서 — 과거 분석은 **비 오는 비닐하우스**에서 나온 게 있다

### 3. 검증 항목을 미리 목록으로

릴리스마다 확인할 항목은 그 릴리스의 KNOWN-ISSUES 항목 중 **`실기기 상태: ⚠️미확인`** 인 것들이다.

```bash
grep -n "실기기 상태.*미확인" KNOWN-ISSUES.md
```

각 항목의 **확인 항목** 문장이 그대로 체크리스트가 된다.

### 4. 로그를 수확한다

로그는 실기기 분석의 1차 소스다([PRINCIPLES.md](../PRINCIPLES.md) §4). 앱은 세션 로그와
음성 클립을 Drive에 zip으로 올린다(설정 탭에서 확인).

분석할 때 보는 것:

- **값 오염 0건인가** — 시트 값과 클립 발화가 일치하는가 (클립 감사)
- **STT 사망이 있었나** — `lifecycle:*`, `zombie_restart`, `mic_auto_reconnect:*` 연쇄
- **경보가 발동했나** — `trend_alert_fired`
- **오디오 경로가 바뀌었나** — `audio_route_revalidate`, `mic_teardown`
- **행 처리** — `row_complete` / `row_skipped` 와 complete·synced 카운트

> ⚠️ **계측 부재는 "문제 없음"이 아니다.** 이벤트가 안 남았다는 건 그 경로를 관측하지 못했다는
> 뜻일 수 있다. 실제로 `[STT-14]` 인식기 영구 사망은 **기존 계측으로는 관측 자체가 불가능**했고,
> 전용 lifecycle 텔레메트리를 새로 넣고서야 보였다. 백스톱이 발동하지 않은 것은 **효능 미확인**이지
> 효능 확인이 아니다.

### 5. 판정을 KNOWN-ISSUES에 기록

세 필드를 분리해서 적는다:

```
- **당시 상태(YYYY-MM-DD):** …
- **현재 상태:** …
- **실기기 상태:** ✅확인됨(측정값·세션 수 포함) / ⚠️미확인 / ➖해당없음
```

`✅확인됨`으로 올릴 때는 **무엇을 몇 건 봤는지** 쓴다. 예: "값클립 71개 silencedetect,
앞공백 max 0.31s, 0/71 ≥ 0.6s". 숫자 없는 "확인함"은 다음 사람이 재판정할 수 없다.

확인이 끝난 항목은 `RESOLVED`로 [KNOWN-ISSUES-ARCHIVE.md](../KNOWN-ISSUES-ARCHIVE.md)에,
계속 지켜야 할 규칙이 남으면 [ENGINEERING-GUARDRAILS.md](../ENGINEERING-GUARDRAILS.md)에
옮긴다.

## 데스크톱 근사 테스트

`tests/` 안에 실기기를 근사하는 축이 있다. **판정용이 아니라 회귀 방지용**이다.

- `safe-area.spec.ts` — `iphone17` 프로젝트(402×874 @3x). 브라우저가 노치 inset을
  시뮬레이션하지 않으므로 `tests/fixtures/safeArea.ts`가 `--sat`/`--sab` CSS 변수를
  override해 재현한다.
- `tests/fixtures/stt.ts` — STT 목 SSOT. 실제 인식기가 아니다.

## 현재 미확인 항목 (2026-07-26 기준)

`KNOWN-ISSUES.md`에서 `실기기 상태: ⚠️미확인`을 검색하면 최신 목록이 나온다. 큰 것만:

- **화면 회전 시 흔들림** — 원인 가설(ResizeObserver 자기관측)이 실측으로 **반증**됐다.
  진짜 원인 미상, 재현 자체가 데스크톱에서 안 된다. (v0.39.0)
- **경보 문구의 TTS 발음** — `:`를 어떻게 읽는지/멈추는지 미확인. (v0.39.0, 가드레일 ③)
- **마이크 자동 재연결 효능** — `[CLIP-R1]` 수정 후 실기기 발화 여부 미관측. (v0.38.0)
- **재로그인 후 입력방식 유지** — 시즌 첫 회차처럼 행이 적은 시트에서. (`[SETTINGS-1]`, v0.38.0)
- **글로우 발열·배터리** — 상시 rAF 구동의 실사용 영향.
